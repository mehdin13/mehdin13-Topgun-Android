## Localization
- Languages: English (default), Persian (fa, RTL), Arabic (ar, RTL), Spanish, French, German, Turkish, Russian. `AppLanguage` (data/) lists them; the choice is stored in `AppPreferences.language` (null = follow the device). Settings > Preference > Language opens `LanguageScreen`; selecting a language saves it and `MainActivity` recreates itself, applying the locale and layout direction. No `resConfigs`/`localeFilters` restriction and no `locales_config.xml` / `generateLocaleConfig` is needed, because the language is applied by our own code, not by the system per-app language picker.
- Strings live in `app/src/main/res/values*/strings_group_*.xml` (one file per feature group, same file name in every `values-xx` folder). Group C (auth, intro, paywall, settings, splash, navigation, errors) is `strings_group_c.xml` with prefixes `auth_`, `intro_`, `welcome_`, `nav_`, `settings_`, `error_`. Shared: `strings.xml` (`app_name`, `language_title`, `language_system_default`, `selected`, `not_selected`). Brand "Top Gun" is never translated; backend text is shown as received.
- ViewModels hold `UiText` (data/UiText.kt: `UiText.Raw` or `UiText.Res(id, args)`), resolved in the UI with `@Composable UiText.asString()` or `asString(context)`. `ApiError.localized()` is the localized counterpart of `ApiError.userMessage` (which stays English in `:core`); screens not migrated yet still use `userMessage`.
- Add a language: (1) add an entry to `AppLanguage` (code, native name, `rtl`), (2) add `values-xx/strings_group_*.xml` for every group file with every key (same format specifiers, plurals with the quantities of that language), (3) add the code to the backend `SUPPORTED_LANGUAGES` (sent as `Accept-Language`).
- `tools/compose-check/check.sh` now also generates `R.plurals.*`; the shim `Context` has `getString`.
